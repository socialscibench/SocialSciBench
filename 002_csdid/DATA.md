# Task 002 real workloads (combined task)

This task combines the former tasks 002 (the core of Stata's `csdid`), 002b (its common options)
and 002c (the options published replication packages add): one reference, one loader and 15
workloads. `realdata.py` loads each workload into the arguments of `reference.run`: `y` (NaN where a
unit is not observed), covariates `X` (fixed, or varying over time as [n_units, n_periods, k]),
`gvar`, the sampling weight `w` (or `None`) and the settings (`control`, `method`, `event_window`,
`base_period`, `trim`, `boot_weights`, `event_sets`, `rules`). The bootstrap's +1/-1 multipliers
are generated by the loader from a fixed seed (NumPy PCG64 seeded with the workload number), so the
bootstrap is deterministic. Loading and generating the multipliers are outside the timed call;
the sample rules, every cell's estimation, influence functions, aggregations and the bootstrap
are inside it. `real_workloads.json` pins the input files and splits.

| Suite | IDs | Permitted use |
|---|---|---|
| `synthetic` | 1-6 | The former task's synthetic panels with the default options |
| `real-development` | 101-109 | PatentsView, technology areas A-F |
| `real-heldout` | 301, 302, 401-404 | Frozen final evaluation: SEC insider filings, QCEW employment |

> **Not evaluated in this submission:** the `real-heldout` workloads are defined for a future frozen
> final evaluation and were not run. Every result reported with this repository uses the development
> and synthetic workloads.

## Development coverage

These are input descriptions, not estimator results. Each workload follows the rules of csdid
1.81 (`csdid181`) or 2.0.1 (`csdid201`).

| 102 | Firm event: first alliance; firms exit | 4,532 x 30 | never | dripw | yes | unbalanced | varying | analytic | 1.81 |
| 103 | Firm diversification, 10 covariates | 10,000 x 20 | never | reg | - | balanced | universal | analytic, event subsets | 2.0.1 |
| 104 | Inventor job moves, monthly, 3,481 cells | 10,000 x 60 | never | dripw | - | balanced | varying | analytic | 2.0.1 |

The package's author compared the reference with Stata `csdid` 2.0.1 on the development workloads
that follow 2.0.1's rules (101, 103, 104, 105, 107: estimates within 2e-7; the bootstrap agrees
statistically); the 1.81-rule workloads were validated component by component against csdid 1.81
in the former packages. Covariate order follows the Parquet schema; outcome columns are ordered by
period; covariates that vary over time are stored as `<name>_t001` ... `<name>_tT`; treatment codes
are periods starting at 2, with 0 for never treated. Unit identifiers are not candidate inputs.

## Running and reporting

```bash
python -m harness init-solution --task 002 --out solutions/002/first
python -m harness evaluate --task 002 --solution solutions/002/first/solution.json --smoke
python -m harness evaluate --task 002 --solution solutions/002/first/solution.json --suite real-development --ids 101 107
```

The default development data root is `datasets/002/data`; override it with `--data-root`. Final
evaluation requires an external root, normally `--data-root ~/SocialSciBench-private/002/data`
with the held-out files in `heldout/`. Never use held-out data or results for tuning, debugging or
choosing settings; freeze code and settings with `harness freeze`, run `harness final`, and report
every round.

**Maintainer, before the first freeze:** put the package's held-out files (301, 302, 401-404 and
their manifests) in the private data root, and fill in their sizes and hashes in
`real_workloads.json` (the development agent that integrated the task did not access them):

```bash
python - <<'PY'
import hashlib, json, pathlib
root = pathlib.Path("~/SocialSciBench-private/002/data").expanduser()
path = pathlib.Path("002_csdid/real_workloads.json")
catalog = json.loads(path.read_text())
for w in catalog["workloads"]:
    for f in w["files"]:
        if w["suite"] == "real-heldout":
            data = (root / f["path"]).read_bytes()
            f.update(size=len(data), sha256=hashlib.sha256(data).hexdigest())
path.write_text(json.dumps(catalog, indent=2) + "\n")
PY
```

Until then `harness final` stops at its file check before any round is consumed. The former
task's development data (workloads 101-108 of the earlier version) are kept for the replay of
earlier runs in `datasets/002-legacy-20261023/data`.
