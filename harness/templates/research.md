# Candidate research

## Objective and constraints

Record the task, estimator conventions, target hardware, thread count and experiment budget.

## Sources

Record source URLs, access dates, paper/library versions and relevant implementation details.

## Hypotheses and bottlenecks

Describe each proposed change, its expected benefit and how it will be measured.

## Experiments

Record changes and unsuccessful attempts as well as successful ones. Link each run directory,
including incomplete workloads, correctness failures and timeouts. Report absolute timings,
speedups and the exact cases evaluated; a smoke pass is not full-task certification.

## Reproduction

Keep requirements.lock and build.md current. Record external library versions/build hashes
and any hardware or system dependencies that a Python dependency lock cannot capture.
